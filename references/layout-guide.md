# 布局原理与设计指南

> 本文件说明两件事：**手工布局的坐标带模型**（怎么算坐标才能整齐不重叠），
> 以及**设计者（Claude）如何规划布局意图**（怎么排 layer/lane、怎么分组、
> 怎么走线）。语法细节见 [drawio-xml-guide.md](drawio-xml-guide.md)。

---

## 1. 坐标带模型（不重叠的唯一保障）

没有引擎帮你排版——但引擎时代的**坐标带思维**仍然是手算坐标的最佳方法。
不要逐个拍脑袋写像素坐标，而是：

- **layer（列带）**：横向（左→右图）的一个"列"。同一列的组件属于同一抽象层级。
- **lane（道带）**：纵向的一条"行"。同一行的组件属于同一功能道。

手算规则：

```
第 i 列的 x = 边距 + Σ(前 i-1 列的列宽 + 列距)
第 j 行的 y = 顶距 + Σ(前 j-1 行的行高 + 行距)
组件坐标 = (所在列的 x + 列内居中偏移, 所在行的 y + 行内居中偏移)
```

因为**每一列占据互不相交的 x 区间、每一行占据互不相交的 y 区间**，
任意两个 (layer, lane) 不同的组件在数学上不可能重叠。建议草稿里先列一张
"列宽表 / 行高表"，再机械地累加出每个组件的坐标——比直接想坐标可靠得多。

**默认间距（顶会紧凑密度）**：整图边距 36、列距 40、行距 18-40、
面板间距 26、面板内边距 10 + 标题带 26。所有坐标取 10 的倍数（对齐
draw.io 网格，用户后续手调也舒服）。

### 设计含义
- 想画"并行分支"→ 给它们**不同的 lane**（上下排列）。
- 想画"串联流程"→ 给它们**递增的 layer**（左右排列）。
- 想让两块**纵向对齐**（视觉上成一条直线）→ 给它们**相同的 lane**。

### 容器与面板的几何（最后算）

- **容器** = 成员包围盒 + 12px 内边距；顶部标题再 +16px，底部斜体标题
  +20px，深色标题栏 +26px。
- **面板底板** = 内容包围盒 + 10px 边距 + 26px 标题带；底板在 XML 里
  排在内容**前面**（先画 = 压底层）。
- 多面板分排：同排左对齐、排间垂直堆叠，排间距 26px。

## 2. 布局设计决策清单（每次生成前自问）

1. **原型**：先按模型类型选五大原型之一（见 ccfa-style-guide 第 1 节），
   打开 `examples/` 里对应范例 .drawio 再动手。
2. **方向**：主流模型适合左→右（序列/NLP/扩散）还是自下而上（视觉特征金字塔）？
3. **层切分**：从输入到输出，自然的"抽象层级"是哪几层？
   典型：`输入 → 嵌入 → 主干块 → 任务头`。
4. **道切分**：哪些组件属于同一条功能道（应该上下对齐）？
   典型：`注意力`与`FFN` 上下排列（它们都在同一个编码器容器内）。
5. **分组粒度**：哪里该用容器圈起来？
   重复块（`×N`）、主干块（Encoder/Decoder）、多模态分支（每支一个容器）。
6. **强调点**：本文的贡献模块是谁？给它更醒目的配色或显式 fill/stroke。
7. **配色**：从 [palette.md](palette.md) 选一套，并解释理由（哪怕在心里）。
8. **成图装裱**：论文投稿加底部图题（"Fig. N. ..."）；多阶段/多子图模型
   用淡彩面板做 (a)(b)(c) 分区（配左侧阶段侧栏）；图例默认底部横贯虚线栏
   （多面板系统图改右侧竖列）。

## 3. 经典布局模板

### 3.1 Transformer / LLM（左→右）

```
layer:  0        1        2         3       4
lane0:  Input → Embedding → [Encoder Block ×N]  → Output Head
lane1:            Pos.Enc.    ┌──────────────┐
                              │ Attention    │
lane2:                        │ Feed-Forward │
                              └──────────────┘
```
- Encoder 容器包住 Attention + FFN 两行；残差连接用虚线从 Embedding 绕过容器回到容器出口。
- 位置编码作为**同层不同 lane** 的侧支，用虚线 `add` 连入嵌入输出。

### 3.2 ViT / 视觉（自下而上）

```
layer(纵):  0       1        2          3
lane(横):  Image → Patch Embed → ViT Blocks ×12 → Classification Head
```
- 图像用 cube + 切块网格示意；特征图尺寸用边标注 `[B, C, H, W]` 逐层变化。

### 3.3 扩散 / 生成（左→右，带侧支）

```
layer:  0        1          2          3
lane0:  x_T(噪声) → U-Net 去噪器 → x_0(图像)
lane1:             t → Positional Embedding → MLP  →(侧支注入去噪器)
```
- 时间步编码作为侧支 lane，用虚线汇入主干。

### 3.4 双塔 / 多模态（上下并行）

```
lane0:  文本 → 文本编码器 ─┐
                          ├→ 融合层 → 任务头
lane1:  图像 → 视觉编码器 ─┘
```
- 两塔在**不同 lane** 严格对齐；汇合处用合并节点（`cat`/`⊕` 小圆）。

### 3.5 多面板系统图（2×2 或成排）

```
侧栏       row0: [ (a) 候选生成 ]  [ (b) 智能体图 ]
竖排阶段带  row1: [ (c) 奖励评估 ]  [ (d) 束搜索 ]   ┌────────┐
                                                    │右侧图例列│
                                                    └────────┘
```
- 每块面板内部是**独立的坐标带**（自己的 layer/lane/方向），互不影响；
- 面板按排拼装：同排左对齐、排间垂直堆叠，相邻面板用不同淡彩（6 套循环）；
- 跨面板边用 2.4px 粗线主色，按两端面板相对位置选 exit/entry
  （右→左或下→上）；反馈回路用粗虚线；
- 左侧每排一条竖排阶段带（宽 40，`horizontal=0`）。

### 3.6 U-Net / Encoder–Decoder 对称 U 型（左→右，skip 走外环）

```
layer:  0        1            2            3        4
lane0:  Input ─ Encoder ─┐  ┌─ Bottleneck ─┐  ┌─ Decoder ─ Output
                        └─│ (×N TBlock)  │─┘
lane1:  (skip 虚线沿容器顶部外环绕行)  (不穿兄弟成员)
```

- **三段水平居中、纵向对齐**：Encoder / Bottleneck / Decoder 三容器同 lane，
  x 等距排开，Bottleneck 置于**正中**（Encoder 右缘与 Decoder 左缘的中间），
  纵向也与其他段对齐——**不许让某一段孤悬一侧、留下大片空白条**
  （Bottleneck 独处中右、左侧空一列是本 skill 的高发事故）；
- 重复子块（TBlock/Block ×N）在容器内**水平排开、间距 ≥ 成员高**；容器宽
  按成员包围盒 + 内边距算，别为了"对称"把容器拉得比内容宽一截；
- 成员→容器外的出边，先确认直出走廊里没有**兄弟成员**挡路（见 §4 铁律：
  换 exit 侧 / 加拐点绕行 / 挪目标）；
- skip/跳跃用虚线，沿**容器上方或下方外环走廊**绕回，不穿兄弟成员；
- 画自下而上的视觉金字塔 U 型时原理相同，方向轴换 y、lane 语义互换。

## 4. 走线与标注的细节规矩

- 主流程边：`#5F6368` 深灰实线，`strokeWidth=1.2`。
- 残差/跳跃/侧支/训练监督/反馈回路：`#9AA0A6` 灰色 `dashed=1`（顶会惯例）。
- 跨面板/系统主干：`#C0762C` 主色 `strokeWidth=2.4`。
- 操作标注（⊕ ⊗ Σ ↑）用 op 小圆节点；张量形状标注（`B×L×d`）写在
  **主流程边**的 label 上，全图统一一种写法、简短；带文字的边必须
  `labelBackgroundColor=#FFFFFF`，否则文字悬空压线。
- **端口分散（槽位公式）**：某节点同一侧 k 条边 → 槽位取 (i+1)/(k+1)
  （k=2 取 0.333/0.667，k=3 取 0.25/0.5/0.75），**按对端位置排序分配**
  ——对端在上面的边拿小号槽位，这样同侧出线保持相对顺序、互不交叉。
  回连/残差反向边镜像到另一侧。
- **合流例外**：从相反方向汇入同一个 op 小圆/汇聚点的边允许共享端口
  （视觉上是干净的叉）；**同方向并行**的边共享端口 = 两线全程叠成一股，
  绝不允许。
- **枢纽居中**：多入多出的节点（融合层、汇聚圆、共享空间）放在分支
  中间，让边短而放射；放偏了必然出现横跨全图的长交叉线。
- **长边走外环**：跨多个 layer/lane 的边沿图的外圈走廊或面板缝隙绕行，
  不从图元密集区中间穿过；列距/行距就是天然走线走廊，走廊里不放图元。
- **箭头净空**：最后一个拐点到目标图元的直线段 ≥20px。
- **绕行**：边穿过无关图元时加 `<Array as="points">` 拐点；不要为了绕一根
  线打乱整个网格——先换端口侧，再加拐点，最后才考虑挪组件。
- **容器成员出口边不得穿兄弟成员（铁律）**：容器内某成员的出边若目标在
  容器外，无拐点的正交边会被 draw.io 横平竖直地硬切，一旦撞上同容器的
  **兄弟成员**就是"走线穿过子框图"事故（`unet_transformer.drawio` 里
  Decoder/Bottleneck 的走线穿 TBlock 正是这种）。落笔前先沿目标方向找该
  成员到容器壁的**直出走廊**，确认走廊里没有兄弟成员挡路。有则三选一：
  ① 换 exit 侧（从背对兄弟成员的那一侧出）；② 加 `<Array as="points">`
  拐点沿成员下方的行距走廊绕；③ 挪目标/成员到能直出的位置。校验器对
  无拐点正交边按曼哈顿路径检查，报 WARNING `edge '…' auto-routed across
  sibling member '…'` 即命中。
- **工具兜底**：写完跑 `python3 scripts/validate.py <file>`；未钉端口
  堆叠跑 `edgeports.py`，已钉撞槽跑 `respread_ports.py`。

## 5. 布局排错的思路

如果导出预览图出现不理想的情况，按以下顺序排查：

| 现象 | 原因与修法 |
|---|---|
| 想对齐的没对齐 | 让它们共享 lane（左右图）或共享 layer（上下图）；检查坐标是否都取 10 的倍数 |
| 两分支太挤 | 加大行距，或给分支之间插入一个空 lane |
| 容器没包住该包的东西 | 重算容器几何：成员包围盒 + 12px + 标题形态外扩量 |
| 容器标题被成员压字 | 成员侵入 24px 标题带：成员下移，或容器加高 |
| 成员骑跨容器边 | 调整成员或容器边界，使其完全在内或完全在外 |
| 线交叉多 | 减少跨 lane 的长边；把关系近的组件放到相邻 lane；枢纽节点移到分支中间 |
| 同侧多线叠成一股 | 端口没按对端位置排序分散——按槽位公式 (i+1)/(k+1) 重钉，或跑 edgeports.py / respread_ports.py |
| 预览里线条细得看不见 | 内容宽 >2200px 被整体缩小：缩列距/换方向/拆面板 |
| 图太宽/太窄 | 调列距/行距/组件宽度；或改方向；或拆 (a)(b) 面板 |
| 文字溢出框 | 缩短 label（`&lt;br&gt;` 断行）或加宽组件 |
| 边穿过中间组件 | 先换 exit/entry 侧，再加 `<Array as="points">` 拐点沿外环走廊绕行 |
| 容器成员出边穿兄弟成员（走线穿子框图） | 换 exit 侧背开兄弟成员，或加拐点绕成员下方的行距走廊，或挪目标到能直出的位置（见 §4 铁律） |
| 面板标题与深色标题栏相碰 | 标题栏分组顶部要留 26px；把该分组成员整体下移一行距 |
| 跨面板粗边穿过中间面板 | 改从面板间缝隙走（加拐点），或减少跨排跳跃 |
| 导出失败/预览 400 | 预览导出**不要 `-e`**、用 `--width 2000`；见 xml-guide 第 8 节 |

> 布局的**每个决定都服务于"讲清楚一个故事"**。规则的对齐让你安全，
> 自由的选择让你出彩——两者并不矛盾。
