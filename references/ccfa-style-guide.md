# CCF-A 风格模型架构图指南

> 目标读者：Claude（以及想手工微调的用户）。本文件回答一个问题：
> **"什么才是一张合格的 CCF-A 顶会论文级架构图？"** 让生成的图在
> NeurIPS / ICML / ICLR / CVPR / ICCV / ACL / EMNLP / AAAI / KDD 等会议中看起来"属于那里"。
>
> 本 skill 不写生成脚本——你直接手写 .drawio XML。语法与样式串见
> [drawio-xml-guide.md](drawio-xml-guide.md)；本文件管"画什么、怎么排才像顶会"。

## 0. 顶会生图提示词说了什么（权威风格来源）

本 skill 的 CCF-A 风格不是拍脑袋，而是从 `ccfa_prompts/` 里 **8 份真实顶会
论文图的生图提示词**（positive + negative prompt，覆盖遥感重建 / 医学分割 /
持续学习 / 多模态推理 / 视频异常检测 / 多智能体 / 立场检测 / 视频生成）提炼的。
它们的要求高度一致：

| 维度 | 一致规范 |
|---|---|
| 整体 | Adobe Illustrator 矢量平面图、**纯白背景**、扁平化、**黑色细实线** |
| 形状 | **统一圆角矩形**模块；平行四边形/箭头表达张量与流程 |
| 明令禁止 | **无 3D 透视、无阴影、无渐变、无贴图/照片质感、无发光、无粗线、无卡通装饰、无遮挡文字** |
| 配色 | **低饱和度、半透明淡彩**：浅蓝 / 米黄 / 浅粉 / 橙黄 / 浅绿 / 浅紫；容器用**半透明背景框** |
| 字体 | **Times New Roman 黑色**，数学变量用 LaTeX（`$\mathcal{L}$`、`$X_{vid}$`） |
| 构图 | **横向宽幅**、左→右数据流；多子图用 **(a)(b)(c) 分区**；**总图 + 下方子模块放大** |
| 容器 | 彩色**虚线**背景框圈住阶段/方法，模块排布整齐、残差连接清晰不杂乱 |
| 图例 | **底部横贯整图的虚线图例栏**（或右上角图例框），含操作符符号（⊕ 相加 / ↑ 上采样） |
| 图题 | **底部** "Fig. 1. Overall framework of ..." |
| 线型 | 实线 = 前向主流程；**虚线 = 残差 / 训练监督 / 反馈回路 / 侧支** |
| 张量 | 形状标注 `B×h×w` / `C×H×W`，特征名 `F0 / F1 / F_prior` 等 |

> 默认配色（`ccfa-standard` 色板 + Times New Roman + 底部图例栏 +
> 半透明容器 + 底部图题）就是为了复现这一风格，色值全部在
> [palette.md](palette.md) 里抄即可。你几乎不需要发明颜色，
> 专注把模型讲对、把部件画全即可。

## 1. 五大图型原型（按模型类型选画法）

**没有一种"统一的顶会风格"。** 对 10 张真实 CCF-A 论文图（ccfa_png/model1–10）
的分析表明：不同类型的模型对应完全不同的图型。动手写 XML 之前，先判断
用户的模型属于哪个原型，再按该原型的配方组织画面——**每个原型在
`examples/` 都有验证过的 .drawio 成品，照它的样式串写**。
**选错原型 = 图画得再整齐也不像顶会图。**

| 原型 | 适用模型 | 版面 | 参考实例 | 范例 .drawio |
|---|---|---|---|---|
| **A. 流水线+子模块放大** | CNN/Transformer 等单一神经网络骨干 | 一条水平长条主干 + 分组容器 + 底部斜体组标题 | model1, model2 | `examples/pipeline_zoom.drawio` |
| **B. 多面板训练图** | 训练流程/持续学习/多阶段方法 | (a)(b)(c) 独立小面板，各自完整，粗箭头跨面板衔接 | model3, model4 | `examples/multipanel_train.drawio` |
| **C. 多智能体/系统分区图** | 多 Agent 系统、RAG、LLM 框架 | 2×2 或一排彩色大面板 + 粗色跨面板箭头 + 左侧阶段侧栏 + 右侧图例列 | model5, model7, model8, model10 | `examples/agent_panels.drawio` |
| **D. 推理阶段容器图** | CoT/推理链/规划方法 | 2-3 个横向大阶段容器，内部"步骤模块+便签气泡"，底部挂小面板 | model9 | `examples/reasoning_stages.drawio` |
| **E. 横带框架图** | 多模态大模型、统一框架 | 3-4 个能力面板并排 + 深色标题栏分组 + 底部训练配方横带 | model6 | `examples/framework_bands.drawio` |

### 原型 A：流水线 + 子模块放大（单一网络骨干）

- **版面**：水平长条（左→右）。主干组件全部放主道带，
  侧支（先验提取、全局跳跃）放上方/下方副道带。
- **图元**：输入/输出用 cube 立方体（图像块）；卷积/归一化/激活长链用
  vbar 竖条（`horizontal=0` 竖排文字，这是顶会网络图最标志性的图元）；
  融合点用 op 小圆（⊕ ⊗ Σ ↑，34×34 白底细边、符号加大加粗）；
  上采样模块用醒目填充色。
- **分组**：功能阶段用彩色半透明背景框（实线边 + 低饱和 fill），
  标题用**底部居中粗斜体** text 单元格（如 *Shallow Feature Extraction*）；
  重复块写 `×N`。
- **标注**：边上标特征名/形状（`F0`、`F_prior`、`B×h×w`）；主干旁边画
  跳跃连接虚线成环。
- **图例**：底部横贯虚线栏，条目 = 层类型色块 + `⊕`/`↑` 操作符圆圈。
- **密度基准**：20+ 组件、25+ 条边；列距 ≈34、行距 ≈26-40。

### 原型 B：多面板训练图（(a) 训练 (b) 迁移 (c) 测试）

- **版面**：2-4 块淡彩子图面板，(a) 占第 0 排（最复杂），其余小面板占
  第 1 排。每个面板是一个**自包含小图**（自己的输入/输出/损失）。
- **图元**：数据快照用 cube；阶段间迁移用 singleArrow 实心大箭头；蒸馏目标
  用 matrix 矩阵网格（复合图元，画法见 xml-guide）；冻结模型用灰填充 +
  `dashed=1` 虚线描边。
- **衔接**：跨面板粗边（2.4px、`#C0762C` 主色）表达"训练产物 →
  迁移 → 测试使用"的故事线。
- **图例**：冻结/可训练色块 + 蒸馏(虚线)/前向(实线)线型对照。
- **密度基准**：主面板 15-20 组件，小面板 3-6 组件；宁可拆面板不要挤一张图。

### 原型 C：多智能体/系统分区图

- **版面**：4 块子图面板（2×2）或 3 块一排；每面板一个子功能（候选生成 /
  智能体图 / 奖励 / 搜索），各配淡彩底色（6 套循环色见 xml-guide 第 5 节）。
- **侧栏**：左侧竖排阶段带（"1. Prompt Optimization" /
  "2. Reward & Search"），每排一条，`horizontal=0` 竖排文字。
- **图元**：LLM/Agent 用带 emoji 的模块（🤖👤，draw.io 原生支持）；
  样本库用 cylinder3 圆柱；公式/评分用 note 便签；搜索树用椭圆节点 +
  概率边标签。
- **衔接**：跨面板**粗箭头是主角**——系统数据流全部走粗色边；反馈回路
  （如 p_best 回传优化器）用粗虚线。
- **图例**：右侧竖排图例列（画布右侧加宽 200px），内容 =
  冻结/可训练 + System Flow(粗线样) + Feedback(虚线样)。
- **密度基准**：每面板 4-8 组件；跨面板边 4-6 条构成闭环故事。

### 原型 D：推理阶段容器图（CoT / 规划）

- **版面**：2 个宽大阶段面板横排（Perception → Cognition），底部挂
  1-2 个小面板（答案结构 / 数据集安排）。
- **图元**：阶段内的每一步用**加粗步骤模块**（"Step 1: Global Perception"），
  步骤产物用 note 便签气泡（"Abnormal Event Description + Spatial
  Location"）；答案扇出用中心椭圆 + 卫星小框（What/When/Where…）。
- **衔接**：阶段间一条粗边（步骤产物 → 下一阶段）；便签之间用带标签的
  细边（"holistic observation"、"visual cues"）——**标签就是推理链的文字**。
- **密度基准**：每阶段 4-6 组件；步骤必须编号（Step 1/2/3/4）。

### 原型 E：横带框架图（统一多模态框架）

- **版面**：上排 3 个能力面板并排（理解 / 核心 / 生成），下排 1 个训练
  配方横带面板。
- **图元**：核心 LLM 用大灰框（frozen）+ LoRA 小红框；数据用 cylinder3；
  文本用 document；图像用 cube。
- **分组**：每个能力栈用**深色标题栏分组**——容器无标签，顶部叠一根
  24px 深海军蓝条（`#2E3A4E` + 白字粗体），这是横带框架图的标志。
- **衔接**：能力面板之间粗边（visual tokens / gen. hidden 汇入核心）。
- **密度基准**：每面板 3-5 组件 + 1 个深色标题栏分组；训练带 2 个 Stage
  分组并排。

### 1.0 原型不是枷锁

五个原型覆盖主流，但组合是常态：多模态 Agent 系统 = C 的版面 + E 的
深色标题栏；带推理链的网络 = A 的主干 + D 的步骤便签。**规则只有第 4 节
铁律那 8 条**；原型只是起点模板。

## 2. 一张好架构图的信息层次

CCF-A 论文的架构图在画面密度与可读性之间达成精确平衡。它通常只表达
**一个核心故事**，并通过三个信息层次组织：

| 层次 | 内容 | 示例 |
|---|---|---|
| **主干 (backbone)** | 数据如何流经模型主体 | `输入 → Encoder ×N → Decoder → 输出` |
| **部件 (modules)** | 每个主干块内部的关键操作 | Attention、FFN、LayerNorm、残差连接 |
| **细节 (annotations)** | 张量形状、操作符、可学习的加粗强调 | `B×h×w`、`⊕`、`×N`、`softmax` |

**要点：** 主干用粗线条的箭头 + 规则网格对齐表现，部件用分组容器收纳，
细节用灰色小字标注。三者缺一不可。

### 2.1 可复制的"部件清单"检查表（防止漏画）

生成图之前，把模型的部件过一遍这个清单。清单上该有的、且模型里真实存在的，
都必须出现在图上——这是"完整性"的保证，比美观更重要。

- [ ] **输入**：原始输入形式（token 序列 / 图像 patch / 图结构 / 特征向量 / 噪声）
- [ ] **嵌入/编码**：embedding、patch embedding、one-hot、位置编码
- [ ] **主计算块**：每个自注意 / 卷积 / RNN 单元 / 图聚合算子 / 扩散步骤（标注 ×N）
- [ ] **块内子模块**：Attention、FFN、CNN 卷积、归一化(LayerNorm/BatchNorm/GroupNorm)、激活
- [ ] **残差/跳跃连接**：skip connection 是否成环、相加还是拼接
- [ ] **池化/下采样**：pooling、stride、downsample
- [ ] **上采样/重建**：upsample、deconvolution、decoder 分支
- [ ] **任务头**：分类头、回归头、decoder 输出、生成头
- [ ] **损失/约束**：loss 计算位置（若对整体理解重要）
- [ ] **多分支/多模态输入**：每个输入流的完整路径

> 读代码时：以 `forward()`/`__call__` 的调用顺序为线索，把每个 `self.xxx`
> 子模块、每个张量变换都对应到清单上。**宁可多列一个组件，不可漏掉真实存在的**
> ——没有任何脚本能帮你查"漏画"，漏画只能靠这份清单在动笔前拦住。

### 2.2 完整性承诺分级（诚实承诺，不夸大）

完整性的兜底责任在**生成前**，且按输入形式诚实分级：

| 输入形式 | 完整性的保障 |
|---|---|
| **模型代码** | `forward()` 调用链逐模块登记，清单逐项核对，一个不漏 |
| **详细口头描述** | 按第 2.1 清单逐项核对，缺的部件先追问用户 |
| **含糊输入（只给模型名/一句话）** | **先调研再画**：查 1-2 篇权威资料（论文原文/官方文档/arXiv 摘要）提炼主干部件，再走清单 |
| 调研查无权威资料 | 按**最接近的知名架构**画模板，交付时**逐条标注假设/待确认部件**，请用户复核 |
| 文献与用户描述冲突 | **以用户描述为准**，文献只用来补漏（用户的模型常是改过型的） |

调研是 Step 0 的一部分（见 SKILL.md）：用户给的信息越含糊，调研就越要紧。
不要因为"用户只说了个模型名"就凭记忆硬画——去查那篇论文/官方文档，让部件
清单建立在真实结构之上。

### 2.3 密度基准（防止"宽松简陋"）

顶会图是**高密度**的。生成前自查：

| 原型 | 组件数 | 边数 | 标志 |
|---|---|---|---|
| A 单网络长条 | ≥ 15 | ≥ 18 | 主链上每个 Conv/Norm/激活都有竖条，不是 3 个大框 |
| B/C/E 多面板 | 主面板 ≥ 8，全图 ≥ 20 | ≥ 20 | 每个面板都是一个能独立读懂的小图 |
| D 推理阶段 | 每阶段 ≥ 4 | ≥ 12 | 步骤编号 + 便签产物 + 带标签的连接 |

**"稀疏"的典型症状**：全图只有 5-8 个大框、没有操作符小圆、边上没有
张量/特征标注、没有残差虚线、图例只有色块没有符号。中了两条以上就回到
部件清单补料——把 `forward()` 里的每一层都画上。

## 3. 视觉惯例（顶会实况）

### 3.1 流向与对齐

- **NLP / 序列 / 扩散模型**：主流向 **从左到右（LR）**。
- **CV / 视觉模型**：常用**自下而上（TB）**，特征图尺寸逐层缩小。
- **多阶段 / 多分支模型**：可以在一个图中混合——主流程用粗箭头，
  分支用细线引出；但**每个分支自身的流向要保持一致**（多面板图里
  每个面板可以有自己的方向）。
- 所有同级模块**严格对齐在网格上**（按 xml-guide 第 7 节的列带/道带
  手算坐标）。同一列代表"同一抽象层级"，同一行代表"同一功能道"。

### 3.2 形状语义

顶会图里形状是有含义的，不要混用（style 串见 drawio-xml-guide 第 2 节）：

| 形状 | 含义 |
|---|---|
| 圆角矩形 | 计算模块 / 网络层 |
| 平行四边形 | 张量 / 序列 / 特征条 |
| 椭圆 | 汇聚点 / 状态节点 |
| 菱形 | 条件分支 / 选择 |
| 小圆操作符（34×34） | ⊕ ⊗ Σ ↑ 等逐元素运算 |
| 竖条（horizontal=0 竖排文字） | Conv/BN/激活长链 |
| 立方体（shape=cube） | 图像 / 特征图块 |
| 圆柱（shape=cylinder3） | 数据集 / 样本库 / 码本 |
| 文档（shape=document） | 文本片段 / 指令 |
| 便签（shape=note） | 示例气泡 / 公式 / 步骤产物 |
| 矩阵网格（复合图元） | 相似度矩阵 / 蒸馏目标 |
| 实心大箭头（shape=singleArrow） | 阶段间迁移 / 变换 |
| 半透明容器 / 淡彩面板 | 分组 / 重复块 / 子图分区 |

### 3.3 线条与箭头

- 主流程箭头：实线、深灰（`#5F6368`），`strokeWidth=1.2`，**填充实心箭头**
  （`endArrow=block;endFill=1`）。
- **跨面板/系统主干**：粗线 `strokeWidth=2.4`、主色 `#C0762C`——
  多面板图里粗箭头是视觉主轴。
- **虚线 = 残差/跳跃连接、侧支注入、训练监督、反馈回路**（如损失回传、时间步
  嵌入注入去噪器、教师网络监督）；`#9AA0A6` 灰色 `dashed=1`。
- 操作标注（⊕ ⊗ Σ ↑）用 op 小圆节点；张量形状标注写在实线边上。
- 箭头必须"有头有尾"——每根线 source/target 都指向真实存在的图元 id，
  不悬空。
- 残差连接要"清晰不杂乱"：交叉尽量少，紧邻的模块残差画直些；穿过无关
  图元的边加 `<Array as="points">` 拐点绕行。

### 3.4 标注（annotation）

- **张量形状**写在边上或组件角标，灰色小字。**全图统一一种写法**，推荐顶会
  常用的乘号形式：`B×h×w`、`B×L×d`、`C×H×W`（也可统一用 `[B, L, d]`）。
- **重复块**用 `×N` 标注在容器标题里，如 `Decoder Layer ×6`；不要真的画 6 个。
- **操作符**（⊕ 逐元素相加、cat 拼接、↑ 上采样、⊙ 门控）用 op 小圆节点
  并进图例。
- **数学变量 / 损失**用 LaTeX 风格：`ℒ`、`ℒ_svi`、`ε_θ`，保持斜体直觉。
  数学单元（公式、损失、带下标的变量、张量形状）一律**加粗**（`fontStyle=1`），
  与普通标注区分——validate.py 报 `formula cell … is not bold` 即漏加；
  判定信号：上下标 Unicode、希腊字母、数学运算符（√ ℒ ∑ ∫ ⊗ ⊕ − × ² ³ ≈ ∈ ≠
  ← → ± ∪ ∩ ~ 等），以及被比较/大括号包围的下划线（`|B_mis| < K_mis`）。
- 标注字号 **比模块名小 1-2 档**（模块 12、标注 10），形成视觉主次。

### 3.5 字体与排版

- 默认 **Times New Roman**；英文与数学符号走 Times，中文标签 draw.io 自动
  回退到系统中文字体，中英混排不会缺字。
- 全图文字默认**近黑色**（`#202124` 一类，由调色板决定），不花哨。
- 模块名可加粗（`fontStyle=1`）；子标注不加粗；容器标题加粗略小；
  底部组标题用粗斜体（`fontStyle=3`）。
- 文字**居中于框内**，四周留白（`spacing`），换行用 `&lt;br&gt;`。
- 结构标签（loss、×N、张量形状）保留英文更专业。

### 3.6 颜色

- 默认 **`ccfa-standard`**：低饱和淡彩，直接对应顶会提示词的六色语言——
  浅蓝(input/tensor)、浅紫(attention)、米黄(positional)、橙黄(residual)、
  浅粉(loss)、浅绿(output)。全部色值见 [palette.md](palette.md)。
- 每张图 **主色 ≤ 3-4 种**，最多 6 种（含灰阶）。用「色相区分功能、明度区分层级」。
- 同一张图内**一个 kind 只对应一种颜色**，并配图例。
- **容器/面板填充半透明**（容器 `fillOpacity=40` 左右；面板 `fillOpacity=55`
  + 低饱和淡彩），做出顶会"背景框"的通透质感，让框内的模块颜色透出来。
- 多面板图里**面板底色即分区色**：相邻面板用不同淡彩（6 套循环色见
  xml-guide 第 5 节），读者一眼认出子图边界。
- 避免大色块纯饱和色铺底；浅色填充 + 深色描边 + 深色文字是默认安全组合。
- 投稿到需要黑白打印的场合，用 `print-grayscale` 色板。

## 4. 好的架构图的 8 条铁律

1. **一个主故事**：画面只服务"模型怎么把输入变成输出"，不堆装饰。
2. **网格对齐**：所有图元落在统一的坐标带上，行、列严格对齐（手算纪律
   见 xml-guide 第 7 节）。
3. **无重叠**：任何两个非容器图元的包围盒不得相交；文字不得溢出框外。
4. **无遗漏**：第 2.1 节清单上的真实部件一个不少——按第 2.2 节的分级承诺
   兜底：代码输入走 `forward()` 登记；含糊输入（只有模型名/一句话）先调研
   再画，查无资料按最接近架构画并标注假设。
5. **有标注、无废话**：形状/操作/重复数都有标注；不写图里看不出来的话。
6. **色彩自洽**：一图一调色板，图例与图内颜色严格一致。
7. **负面清单**（直接取自顶会提示词的 negative prompt，是**禁止项**）：
   - 不要 3D 透视 / 伪立体 / 阴影投影 / 光晕发光；
   - 不要渐变填充 / 材质贴图 / 照片背景 / 高饱和撞色；
   - 不要卡通装饰 / 粗描边 / 手绘涂鸦 / 文字重叠遮挡 / 水印 Logo。
8. **图题与图例各归其位**：论文投稿用**底部图题**（"Fig. 1. ..."）+
   **底部横贯虚线图例栏**；不要把标题当图题放顶部硬塞。

## 5. 常见模型类型的"画法套路"

| 模型类型 | 原型 | 主干画法 | 提示 |
|---|---|---|---|
| Transformer / 语言模型 | A | token→embedding→编码器块→解码器块→输出头 | 编码器/解码器各一个容器 `×N`；注意力与 FFN 上下排列在容器内；残差虚线成环 |
| CNN / 视觉骨干 / 超分网络 | A | 图像块→Conv 竖条长链→上采样→输出 | vbar 竖条 + op 小圆 + cube 图像；底部斜体组标题 |
| ViT | A（TB 亦可） | 图像→patch embedding→Transformer 块→分类头 | 图像用 cube + 切块示意；`B×C×H×W` 标注特征图尺寸逐层变化 |
| 扩散 / 生成模型 | A + B | 噪声→U-Net/去噪器→图像 | 时间步嵌入作为侧支输入；标注 `t`、`ε_θ`；训练流程拆 (a)(b) 面板 |
| GNN / 图模型 | A | 图输入→消息传递层×N→读出头 | 图用节点-边示意；聚合算子用 op 小圆（sum/mean/attn） |
| 持续学习 / 多阶段训练 | B | (a) 训练 (b) 迁移 (c) 测试 | 蒸馏矩阵用 matrix；迁移用 singleArrow；冻结模型灰+虚线 |
| 多模态 / 双塔 / 统一框架 | E（或 A 上下双道） | 能力面板并排 + 核心共享 + 训练带 | 深色标题栏分组；融合处用 op（⊕/cat） |
| 多 Agent / RAG / LLM 系统 | C | 2×2 功能面板 + 粗箭头闭环 + 侧栏 | emoji 标记 Agent/人；cylinder 样本库；右侧图例列 |
| CoT / 推理 / 规划 | D | 阶段容器横排 + 步骤便签链 | 步骤编号；便签写步骤产物；底部挂答案/数据小面板 |
| 推荐 / 序列 CTR | A | 特征→嵌入→交互/注意力→MLP→预测 | 特征向量用并列的小平行四边形 |

> 以上只是起点。**设计权在你（Claude）**：只要满足第 4 节铁律，
> 你可以自由选择方向、分组粒度、强调重点、调色板——这正是"不死板"的含义。

## 6. 成图规范（图题 / 图例 / 子图分区）

把模型画对之后，最后这道"装裱"决定它像不像论文图（单元格写法全部见
drawio-xml-guide 第 5-6 节）：

- **图题**：论文投稿在图**底部**放一个图题 text 单元格，写作
  `Fig. 1. Overall framework of the proposed method.`；演示/汇报在图**顶部**
  放标题 text 单元格。两者可同时存在，互不干扰。
- **图例**：默认**底部横贯整图的虚线图例栏**（一根全宽虚线圆角长条 +
  等距"色样+文字"对），和顶会提示词里的"底部虚线图例栏"一致；省地方用
  右下角小框；多面板系统图用**右侧竖排图例列**。条目色样有三种：色块、
  操作符圆圈（⊕/↑）、线样（实线/虚线/粗线）。
- **子图分区 (a)(b)(c)**：每个子图 = 一块淡彩圆角大底板（先画、压底层）
  + 左上角粗体标题 text（`(a) Training ...`）；面板内边距 10px + 顶部
  标题带 26px，面板间距 26px；分排时同排左对齐、排间垂直堆叠。
- **左侧阶段侧栏**：多阶段系统图每排左侧画一条竖排文字带（`horizontal=0`）。
- **总图 + 下方放大**（原型 A 内部）：主干放在主道带，被放大的子模块放
  下方道带并用容器圈住，容器标题写 `(b) Block details`；从主干的对应模块
  用虚线引出"放大"关系（或靠位置上下对齐，不强行连线）。
- **深色标题栏**（原型 E）：容器顶部叠 24px 深海军蓝标题条——适合
  "能力栈 / Stage"这类需要强分区感的图。
- **半透明背景框**：容器 `fillOpacity=40` 左右；给不同分区的容器指定不同
  低饱和 fill 即可得到顶会常见的彩色框。
